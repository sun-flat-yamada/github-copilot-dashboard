## 1. UI全体レイアウト (データセントリック & 1カラム垂直スタック)

ダッシュボードは、GitHub Pages上で快適に動作するレスポンシブなSingle Page Application (SPA) とする。
ヘッダー部でのデータソース選択とメインナビゲーションでの分析View切り替えを直交化し、原則1カラム垂直スタックと初期折りたたみアコーディオンにより高い一覧性と情報密度を両立する。

> **データセントリック設計の意味**: ここでいう「データセントリック」とは、単なるレイアウト思想（データ選択を画面上部に集約する）にとどまらず、**各Viewの表示内容が常にヘッダー部のアクティブ選択データ（データソース/スコープ/タグ）に対する純粋な写像として振る舞わなければならない**という実装上の要求（SDD-01 FR-9）を含む。グローバルコントロールバー（`ActiveDataSelector` / `ScopeSelector` / `TagFilterBar`）は各Viewの外側の兄弟要素として配置されているため、フィルター変更はViewを再マウントしない。したがって各Viewはマウント時の一度きりの計算に頼らず、アクティブ選択データの変化に追従する実装が必須となる。詳細な設計方針・実装規約・チェックリストは [SDD-15 データセントリック・リアクティビティ設計仕様書](15_data_centric_reactivity_design_spec.ja.md) を参照。

## 2. インタラクション仕様

### 2.1 ヘッダー部アクティブデータセレクター (`ActiveDataSelector`)
ヘッダー部中央にて現在選択されているアクティブデータを明確に表示し、クリック展開により以下3種を瞬時に切り替え可能：
1. **Live Metrics (API連携自動収集)**:
   - 過去1年間（直近12カ月）の月次スコープ切り替え、直近30日の日次スコープ、直近30日集約プリセットを提供。
2. **Monthly Usage Report (月次利用レポート)**:
   - `copilot-data` ブランチに保持されている永続化済み月次レポート（CSV由来）の切り替え。
3. **User Upload File (On-demand)**:
   - 手元の CSV ファイルをドラッグ＆ドロップで即時投入。ブラウザの JavaScript メモリ内でのみ解析・可視化し、サーバーやリポジトリへの外部送信を物理的に行わない完全な Zero-Leakage オンデマンド解析。

### 2.2 複数タグの AND フィルター (`TagFilterBar`)
- ユーザー定義グループの `tags` 属性（例: `["正社員", "リモート", "AI推進"]`）からユニークなタグ一覧を抽出。
- 複数タグの選択に対応し、**AND 条件（すべてに一致）** で表示対象アカウントを絞り込み。
- フィルター適用時は「該当 N / 全体 M 名」の件数バッジおよび「解除」ボタンを表示し、KPIカード、グループ配賦、ランキング、明細テーブル、ディープ分析の全集計母数を一括連動して再集計。

### 2.3 水平分割の厳格制限 & フルレスポンシブ横幅拡張 (Anti-Multi-Column & Fluid Responsive Width)
- 各ページのレイアウトは原則 **1カラム垂直スタック (`flex flex-col space-y-6 w-full`)** とする。
- カードやグラフを横並び（2〜3カラム）に分割することは原則禁止とし、テーブルの横スクロールや折れ線グラフの日付圧縮を根絶する。
- **ウィンドウ最大化時のフルレスポンシブ拡張**: 固定ピクセルや狭い上限（`max-w-7xl`、`max-w-[1600px]` 等）による幅制限を廃止し、適切な左右余白（`px-4 sm:px-6 lg:px-8`）を維持したまま、大画面ディスプレイやウィンドウ最大化時にコンテンツエリア（`<main>`）およびヘッダー・ナビゲーションが自動的に広がるフルレスポンシブ設計（`w-full mx-auto`）とする。
- **例外規定**: ツールバーやフレーム以外の分割を行う場合は、必ず「隣で一緒に見る必然性や用途（例: 予算vs実績の同期対比）」があり、かつ「要素の高さを同一（固定ピクセル）に揃えられる」要素に限る。

### 2.4 逐次開示アコーディオン構造 (Progressive Disclosure)
- **Block 0 (サマリーブロック)**: 最上部に常時展開し、エグゼクティブサマリーや主要KPIを表示。
- **Block 1..N (個別要素ブロック)**: 初期状態はすべてコンパクトに折りたたまれ、タイトル、アイコン、主要指標サマリーチップ（例: `12 部署`、`$6,240.00`）のみを表示。
- **一括開閉コントロール**: コントロールバー右端に `[すべて展開]` および `[すべて折りたたむ]` ボタンを常設。
- **ページ全体連動**: ページ冒頭で選択された軸およびグループは、ランキングウィジェットをはじめとする各コンポーネントにシームレスに同期される。

### 2.4 異常検出・エラーハンドリング仕様 (Error & Warning Detection)
データ取得時（APIレートリミット、権限不足 403、Org/Cost Center API障害等）に異常が検出された場合のUI仕様：
1. **Header Error/Warning アイコン**:
   - ヘッダー右側にシンプルな Error（赤色パルス）または Warning（黄色）アイコンと件数バッジを表示。
   - クリックで「異常検出ログモーダル」をオーバーレイ表示。
2. **異常検出モーダル (ErrorLogModal)**:
   - **ウィンドウサイズ**: 画面幅 80% (`w-[80vw]`)、画面高さ 80% (`h-[80vh]`)。
   - **カードレイアウト**: 1画面に概ね3件程度が視認できるゆったりとしたカード設計。表示件数が多い場合は内部スクロール可能。
   - **3行省略 & 展開表示**: メッセージは1件あたり最大3行（`line-clamp-3`）で省略表示。「詳細を展開」ボタンをクリックすることで完全なスタックトレースやAPIレスポンスJSONを表示。
   - **ErrorLog エクスポート**: 「Export Log」ボタンをクリックすると、タイムスタンプ付きの `copilot_error_log_YYYYMMDD-HHmmss.json` をブラウザから即座にダウンロード。

### 2.5 ユーザー別日次利用トレンド・モデル別内訳ビュー (User Trend Viewer)
- **ユーザー選択**: ドロップダウンによる検索・選択、およびユーザー明細/ランキングテーブルからのダイレクト遷移。
- **モデル種類別積み上げ推移 (Stacked Bar + Line)**:
  - 2026年最新マルチモデル（`Claude 3.7 Sonnet`, `GPT-4o`, `o1`, `Gemini 2.0 Flash`）の日次対話数を積み上げグラフで表示。
  - モデル利用の全体合計値（Total Chats）の折れ線グラフを重ねて描画。
- **開発効率指標**: 日次コード提案数・受諾数および受諾率（%）の推移。

### 2.6 ユーザー明細 & 利用活用明細 (`UserDetailTable` / `MonthlyReportUserTable`)
- **健全なFinOps活用設計に基づく見直し**: 利用量の多さが単純に成果・貢献ではないという思想に基づき、「ランキング」やポディウムメダル（🥇, 🥈, 🥉）による序列表現を廃止。先頭列にはレコードID（`#`）を表示し、ニュートラルな一覧明細として提供。
- **3軸・グループ連動 & 柔軟な並び替え**: 選択された集計軸（Cost Center, Organization, 任意仕訳グループ）および選択グループの範囲内で所属メンバーをシームレスにソート。コード受諾採用数、提案数、AIチャット回数、受諾率、利用料金、非アクティブ日数等の指標降順による並び替えに対応。
- **最終利用日の経過時間併記**: 最終利用日列において、最終利用日時からの経過時間を日数や時間（例: `3日前`, `5時間前`, `本日`）でシンプルに併記。
- **アクション列のスリム化 & ヘッダーInformationポップオーバー**: アクション列にはアイコンボタン（詳細分析/インライン展開、トレンド、診断）のみを配置。テーブルヘッダーのアクション列に新設されたInformationアイコンをクリックすることで、各アイコンボタンの機能説明ポップオーバーが表示され、直感的な操作と情報開示を両立。
- **ユーザー選択 & インライン・ドリルダウン分析 (`UserDrilldownPanel`)**: 各行をクリックまたはアクション列のアイコンを押すことで、該当行直下にアコーディオン形式で詳細診断パネルをシームレスに展開。別ビューへ遷移することなく、FinOpsコスト（月額/日割り/超過請求）、生産性KPI、日次アクティビティ推移・AIモデル利用内訳グラフ、総合AI健全度スコア（0〜100点）および5つの非効率アンチパターン判定と改善処方箋を一覧のコンテキストのまま即座に確認可能。Live Metrics、Monthly Usage Report、User Upload (CSV) のすべてのデータソースで完全動作。
- **ワンクリック遷移**: 各行のアクション列またはドリルダウンパネル内から「トレンド（モデル推移）」および「診断（ディープ分析）」へダイレクト遷移。

### 2.7 Cost Center 予算管理 (Cost Center Budget Cards)
- 各Cost Centerの「上限Budget額」「無料Budget額」「現在使用済みBudget額」「残余枠」をプログレスバー付きでカード表示。
- 80%超過で注意（黄色）、100%超過で警告（赤色アニメーション）。全社合計サマリーバーを提供。

### 2.8 レスポンシブトップヘッダー・生成元リポジトリリンク・Aboutモーダル仕様 (Responsive Header & About Modal)
1. **生成元 GitHub リポジトリリンク (Fork-Safe)**:
   - ヘッダー右側に配置された、生成元 GitHub リポジトリへの外部リンク（`<a>` タグ）。
   - コード内に固定 URL をハードコードせず、実行時生成メタデータ (`indexMeta.repository`) またはアクセス元ホスト名 (`<owner>.github.io/<repo>/`) から動的に URL を解決。フォーク先で `Sync Fork` してもマージ競合が一切生じない。
   - 大画面では `owner/name`、小画面ではリポジトリ名またはコンパクトアイコンを表示。
2. **ヘッダーアクティブデータセレクター (`ActiveDataSelector`) & 分析ビューナビゲーション (`ViewNavigation`)**:
   - **ActiveDataSelector (ヘッダー)**: アクティブなデータソース（Live Metrics, Monthly Usage Report, User Upload File）をヘッダー中央に常時表示。クリック展開で直近1年の月次/日次スコープ、保持レポート、手元ファイル投入を即座に切り替え。ポップアップモーダルは親ヘッダーの CSS `backdrop-filter` (`backdrop-blur`) による包含ブロック（Containing Block）制約や画面外はみ出しを防止するため、React Portal (`createPortal`) を用いて `document.body` 直下にマウントする。また、タブ切り替え時にモーダル位置が上下に動くのを防ぐため、画面中央揃えではなく上部固定オフセット（`items-start pt-16 sm:pt-20`）に配置し、縦方向サイズを固定（`h-[600px] max-h-[calc(100vh-5.5rem)]`）した上で、ヘッダー・タブ・フッターを固定（`flex-shrink-0`）し、コンテンツ領域（`flex-1 min-h-0 overflow-y-auto`）で独立スクロールするレイアウト構造を採用する。
   - **ViewNavigation (ナビゲーションバー)**: 従来のモード切り替えから、分析目的に応じた 6 つの分析ビュー（`overview`, `users`, `trend`, `budget`, `deep_analysis`, `model_radar`）の切り替え構成へ刷新（ランキングはユーザー明細へ統合）。アクティブデータソースの機能互換性（`capabilities`）に応じたビューの活性/非活性を自動制御。
3. **About モーダル & 作成日時表示**:
   - `Fork-Safe Storage` バッジは廃止・削除。
   - `2026.09 LTS` バッジをヘッダータイトル横から削除し、About アイコン（`Info` アイコン）に置き換え。
   - About アイコンをクリックするとモーダルが展開し、分析ページ作成日時を `yyyy-mm-dd hh:MM:ss` 形式で強調表示。仕様バージョン（2026.09 LTS）、生成元リポジトリ（Fork 属性付き）、データ保持期間、管理座席数などのシステムメタデータを集約表示。

### 2.9 ダーク/ライト表示テーマ切り替え仕様 (Theme Toggle & Light Mode)
1. **デフォルト設定**:
   - 初回アクセス時または未設定時は、現在の Dark 調デザイン（Dark モード）をデフォルトとして適用。
2. **UI配置 & インタラクション**:
   - ヘッダー右側のアクションエリアにて、**生成元 GitHub リポジトリリンクボタンの隣にアイコンのみ（Sun / Moon）のシンプルなボタンスタイルで配置**。
   - ダークモード適用時は太陽アイコン（`Sun`）、ライトモード適用時は月アイコン（`Moon`）を表示。
   - クリックにより瞬時にテーマが反転し、`title` および `aria-label` にて切り替え先を案内。
3. **設定の永続化 & FOUC防止**:
   - ユーザーの選択状態はブラウザの `localStorage`（キー: `copilot_dashboard_theme`）に保存され、再訪問時やリロード後も設定を維持。
   - `index.html` の `<head>` 内で即時実行スクリプト（インラインIIFE）を実行し、DOM レンダリング前にクラスを付与することで画面のちらつき（FOUC）を完全に防止。
4. **セマンティックトークン設計 (Tailwind CSS v4)**:
   - `html.light` および `[data-theme="light"]` セレクタ下で、Tailwind CSS v4 の `--color-slate-*` 変数群を清潔感の高いライトパレット（背景 `#f8fafc`、カード `#ffffff`、境界線 `#e2e8f0`、文字 `#0f172a`）にセマンティック再マッピング。
   - Recharts の各種グラフ（グリッド線、X/Y軸目盛り、ツールチップ）も CSS 変数と連動し、両モードにおいて高い可読性と洗練されたコントラストを保証。
